# AntCat ⇄ AntWeb Type Reconciliation

Pipeline for linking AntWeb type specimens to AntCat protonyms, flagging discrepancies,
and (once validated) inserting primary type specimen codes into AntCat protonym records.
Runs as a recurring audit every ~2 months.

Last full run: 2026-06-08.

---

## What this does

AntCat records type information **on the protonym** (the original combination), in two
free-text "taxt" fields: `primary_type_information_taxt` and `secondary_type_information_taxt`.
Specimen codes (CASENT…, and other institutional formats) live inside those fields and are
auto-hyperlinked to AntWeb on save.

AntWeb holds the specimens, each with a `type_status` (e.g. "holotype of Strumigenys alapa
Fisher, 2000"). The type status names the **protonym**, not the current determination — which
is why the join is protonym-to-protonym.

The pipeline answers three questions:
1. Which AntWeb type specimens are **already on AntCat** (code present in a protonym's taxt)?
2. Which are **not on AntCat** and should be added (routed to the correct protonym)?
3. Where do the two databases **disagree** (wrong protonym, wrong rank, or AntWeb name typo)?

## The join

- **Primary key: the specimen code.** Both sides carry it. Matching is format-agnostic and
  case-insensitive — normalize by uppercasing and stripping non-alphanumerics
  (`CASENT0005482`, `casent0005482`, `THNHM-I-00124` all compare correctly).
- **Routing key for unlinked specimens:** protonym name + author surname + year, parsed from
  AntWeb `type_status`, matched against the AntCat protonym export.
- **No synonymy collapse.** Match protonym-to-protonym directly. Subjective synonyms are
  irrelevant (each protonym anchors its own type). Objective synonyms / replacement names are
  the only legitimate shared-type case and are handled explicitly.

## Key parsing rules (learned, do not regress)

- **Author boundary:** a protonym name is the genus plus its lowercase epithets; the author is
  the first capitalized token after that. Multi-author names ("Snelling **et al.**, 2014") must
  not absorb "et al." into the name.
- **Joining words are not misspellings:** strip `var. st. subsp. ssp. r. n. f. m. v.` etc.
  before comparing names. AntCat keeps them; AntWeb does not. A name differing only by a
  joining word is the same name, not an error.
- **Bare type_status** ("holotype" with no protonym name): for a primary type, the specimen is
  the type of its **determined species**. Route via the determination when the species was
  never recombined (determination == protonym name); otherwise use the current-name→protonym
  crosswalk from the taxon export.
- **Rank classes:** primary = holotype, lectotype, neotype, syntype (cotype, type). secondary =
  paratype, paralectotype. `type_status` case varies in AntWeb ("Paratype"/"paratype") —
  lowercase before classifying.

## Tiers (output)

| tier | meaning |
|---|---|
| `already_linked` | code already in the matched protonym's taxt |
| `auto` | not linked, routes to exactly one protonym — insert/paste candidate |
| `ambiguous` | routes to >1 protonym (homonym) — manual |
| `nomatch` | protonym not found by name+year (bare-status, true gap, or AntWeb typo) |

Discrepancies (separate from tiers):
- `misplacement` — code linked to the **wrong** protonym (e.g. *alapa* holotype under *dolabra*).
  Which side is wrong needs case-by-case review; not always AntWeb.
- `rank` — linked to the right protonym but wrong section (holotype ↔ paratype).
- AntWeb `type_status` **name fixes** — correctly linked, but AntWeb's free-text name disagrees
  with AntCat's validated protonym name (gender/spelling). These get fixed **in AntWeb**.

## Workflow

### Inputs (uploaded per session — NOT stored in project knowledge; they're large and refresh each cycle)

1. **AntCat protonym export** — `protonyms_species_typeinfo.jsonl`
   Generated by `export_protonyms.rb` (a saved Rails runner; species-group protonyms only,
   structured type taxt fields). Read-only query.
2. **AntWeb specimen export** — `antweb-all-specimens-YYYY-MM-DD.tsv(.gz)`
   The full AntWeb dump (all institutions). ~900k rows; ~36k carry a type_status.
3. *(optional)* **Taxon export** — `worldants.txt` — only needed for the current-name→protonym
   crosswalk that routes recombined bare-status types.

### Steps

1. Regenerate the AntCat protonym export on the server (see "Server export" below) and download.
2. Pull the latest AntWeb full specimen export.
3. Run `reconcile_types.py` → produces the queue, the AntWeb fix list, and the mismatch file.
4. **Validate** a sample of the `auto` tier against live protonym pages (routing + format).
5. Once trusted, run the **dry-run insert builder** (to be added) → proposes the exact
   before/after taxt for each primary-type protonym; review.
6. Snapshot, then apply primary-type inserts in batches **through the Protonym model**
   (preserves PaperTrail history + validations + auto-hyperlinking), with a before/after
   undo map. Validate by reviewing records.

### 2-month refresh
Rerun steps 1–3, diff against the previous run's applied crosswalk, review only the delta.

### Server export (read-only)
```bash
scp export_protonyms.rb antcat:/var/www/antcat-2/

```

## Safety (the insert step is a PRODUCTION WRITE)

- Snapshot before applying (DO UI).
- Write through the Rails `Protonym` model, never raw SQL — keeps PaperTrail audit trail,
  validations, and on-save hyperlinking.
- Dry-run first; emit proposed taxt for review; apply in batches under a bot user.
- Keep a before/after undo map in addition to PaperTrail's per-record rollback.
- Primary types first. Paratypes (secondary) only after the primary pass is validated.


## Type-info formatting spec (from AntCat wiki — must follow on entry/insert)

Field order in `primary_type_information_taxt` (and secondary equivalents):
`Primary type material: … Primary type locality: … Primary type depository/ies: … Primary type specimen/s: …`

- **Specimen codes:** enter the **bare specimen code, uppercased** (CASENT and AntWeb institutional
  codes alike, e.g. `CASENT0900193`, `AMNH-BUFB80`). AntCat auto-hyperlinks them to AntWeb on save —
  confirmed working for non-CASENT amber codes. The AntWeb URL is only a last-resort fallback if a
  specific code ever fails to resolve (a raw URL renders as ugly link text, so avoid it by default).
- **Multiple codes:** comma-separated. A **consecutive series** uses "to" not "-"
  (e.g. `CASENT0811233 to CASENT0811236`). Default to comma-separation; only use "to" for verified runs.
- **Depositories:** institution abbreviations per https://antcat.org/institutions.
- **Lectotype/neotype designation:** `… (by designation of {citation}).` and add a history item.
- **Multi-source info:** prefix each source's contribution with its citation link.
- **Type notes** (`type_notes_taxt`): validity/error comments; rarely used.

Insert rules encoded in build_inserts.py:
- Bare AntWeb code, uppercased; multiple comma-separated ("to" only for verified runs); URL only if a code won't resolve.
- **Never insert an AntWeb-derived locality** — it comes from the original publication. full_block rows
  carry material + depository + specimen only (needs_locality = yes).
- full_block protonyms also get a **secondary** block (paratypes) when AntWeb has them — no locality.
- **Material-consistency flag:** AntWeb kind vs AntCat material kind (syntype<->lectotype suppressed).
  Specimen link is still added; row flagged in material_flag. Dominant: AntWeb syntype vs AntCat holotype.

Live cross-check lists (logged in): antcat.org/database_scripts/protonyms_with_primary_type_information_taxt
(and the secondary / type_notes / etymology / notes equivalents).

## Files in this project

- `build_inserts.py` — generates `primary_adds.csv`: per-protonym ADD worklist (case, add_text,
  material_flag, needs_locality, AntWeb links). All specimen links included; conflicts flagged.
